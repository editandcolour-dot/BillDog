## 1. Security Findings

### 🔴 CRITICAL — 1

#### S-C1. Hardcoded admin email
- **Locations:** [proxy.ts](proxy.ts#L63), [lib/autofetch/alert.ts](lib/autofetch/alert.ts#L5), [app/api/autofetch/worker/discovery/route.ts](app/api/autofetch/worker/discovery/route.ts#L25)
- **Issue:** `ADMIN_EMAIL = 'editandcolour@gmail.com'` is a string literal in three production files.
- **Risk:** Violates `AGENTS.md` §8 (no hardcoded secrets/identifiers). Personal email exposed in git history + any leaked bundle. Single point of compromise for admin gating.
- **Fix:** Move to `process.env.ADMIN_EMAIL`, fail closed if unset.

---

### 🔴 HIGH — 4

#### S-H1. Rate limiter fails OPEN
- **Location:** [lib/rate-limit.ts](lib/rate-limit.ts#L23-L27)
- **Issue:** On Redis error the limiter returns `{ success: true }`, allowing unlimited traffic.
- **Risk:** Brute-force, DDoS, AI-cost-exhaustion protection vanishes the moment Upstash hiccups (quota, network, expired creds). Violates OWASP A04 (Insecure Design — secure default).
- **Fix:** Return `{ success: false }` on error, alert on repeated failures.

#### S-H2. PayFast validation leaks signature material to logs
- **Location:** [lib/payfast/validate.ts](lib/payfast/validate.ts#L83-L93)
- **Issue:** `console.error` dumps received signature, key order, masked hash inputs across all 6 hash strategies (S1–S6).
- **Risk:** Logs persist to Railway/cloud sinks. Material aids replay attacks and signature forgery research. Violates `AGENTS.md` §8 ("Never log or expose PayFast tokens").
- **Fix:** Gate behind `DEBUG_PAYFAST=1` env, default off in production. Strip in next deploy.

#### S-H3. PayFast tokenise route logs merchant key/passphrase metadata
- **Location:** [app/api/payfast/tokenise/route.ts](app/api/payfast/tokenise/route.ts#L44-L50)
- **Issue:** Logs last 4 chars of merchant ID + merchant key + passphrase length.
- **Risk:** Length + 4-char tail dramatically shrinks brute-force space if logs leak.
- **Fix:** Remove the three diagnostic `console.log` calls.

#### S-H4. Database errors returned to clients
- **Locations:**
  - [app/api/user/profile/route.ts](app/api/user/profile/route.ts#L37)
  - [app/api/user/mandate/route.ts](app/api/user/mandate/route.ts#L24)
  - [app/api/consent/log/route.ts](app/api/consent/log/route.ts#L52)
  - [app/api/cases/[id]/verify/route.ts](app/api/cases/[id]/verify/route.ts#L118)
- **Issue:** `return NextResponse.json({ error: error.message }, …)` exposes Supabase error strings (table names, FK constraints, RLS violations).
- **Risk:** Schema reconnaissance for injection/privilege probing. Violates `error-handling` skill.
- **Fix:** Log server-side, return generic `{ error: 'Internal error', requestId }` to client.

### 🟠 MEDIUM — 5

#### S-M1. CSP allows `unsafe-inline` and `unsafe-eval`
- **Location:** [next.config.mjs](next.config.mjs#L21)
- **Issue:** `script-src 'self' 'unsafe-inline' 'unsafe-eval'`.
- **Risk:** CSP no longer mitigates XSS — the primary defence is voided.
- **Fix:** Move to nonce-based CSP (Next 16 supports this natively).

#### S-M2. Error boundary dumps full error to console
- **Location:** [app/error.tsx](app/error.tsx#L12)
- **Issue:** `console.error('[Error Boundary]', error)` includes stack and any attached metadata.
- **Risk:** Stack frames can contain PII / query params; browser logs may be shipped to monitoring tools.
- **Fix:** Log name + sanitised message + digest only.

#### S-M3. Hardcoded Upstash REST URL
- **Location:** [lib/rate-limit.ts](lib/rate-limit.ts#L7)
- **Issue:** `https://crisp-bunny-73029.upstash.io` hardcoded; `UPSTASH_REDIS_REST_URL` already exists in `.env.local.example` but unused.
- **Risk:** Endpoint identity in git; cannot rotate without code change.
- **Fix:** Read from env, fail closed if absent.

#### S-M4. Missing DELETE/UPDATE RLS on user-owned tables
- **Locations:** [supabase/migrations/022_municipal_autofetch.sql](supabase/migrations/022_municipal_autofetch.sql#L41-L46), [supabase/migrations/027_tariff_cache_v2.sql](supabase/migrations/027_tariff_cache_v2.sql)
- **Issue:** `municipal_credentials`, `scrape_jobs`, `scraped_bills` have SELECT policies but no DELETE; `tariff_cache` / `tariff_research_audit` / `tariff_gaps` lack a written user-blocking policy.
- **Risk:** Defence-in-depth gap if service-role key ever escapes; reference tables potentially mutable by authenticated users.
- **Fix:** Add explicit `DELETE`/`UPDATE` policies (`auth.uid() = user_id`) and confirm tariff tables are write-locked for `authenticated`.

#### S-M5. Profile-completeness redirect lacks rate limiting
- **Location:** [proxy.ts](proxy.ts#L70-L78)
- **Issue:** Every authenticated request hits the `profiles` table; no caching, no rate limit on `/onboarding`.
- **Risk:** Minor enumeration / cost amplification; possible UX issue if profile update races.
- **Fix:** Cache completeness flag in session cookie; rate-limit `/onboarding`.

### 🟡 LOW — 3

#### S-L1. Admin email comparison is case-sensitive
- **Location:** [proxy.ts](proxy.ts#L61-L65)
- **Fix:** `user.email?.toLowerCase() !== process.env.ADMIN_EMAIL?.toLowerCase()`.

#### S-L2. No crypto key rotation / versioning
- **Location:** [lib/crypto/credentials.ts](lib/crypto/credentials.ts), [docs/credential-key-rotation.md](docs/credential-key-rotation.md)
- **Fix:** Add `key_version` column on `municipal_credentials`; document re-encryption job.

#### S-L3. Rate-limit identifier is raw IP
- **Location:** [lib/rate-limit.ts](lib/rate-limit.ts)
- **Fix:** Combine IP with user id (when authed) to avoid penalising shared-NAT users.

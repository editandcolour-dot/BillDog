## 1. Architectural Baseline

* **Payment Flow:** Ad-hoc Tokenisation (`subscription_type: 2`) via hosted checkout. No upfront payments.
* **Component 1:** Backend `api/payfast/tokenise` constructs field data in PayFast's canonical order and applies an MD5 hash over the URL-encoded parameter string.
* **Component 2:** Frontend `[id]/page.tsx` mounts a hidden `<form>` using the generated `data.fields` and auto-submits to `https://www.payfast.co.za/eng/process`.
* **Component 3:** PayFast processes the tokenisation and fires a background webhook (ITN) to `api/webhooks/payfast` to deliver the secure token.

## 2. Identified Faults & Fixes Applied

### Fault 1: Zero-Value Auth Rejection
* **Symptom:** `amount: "0.00"` rejected.
* **Fix:** Hardcoded `amount: "5.00"` (R5 auth/reversal as approved by PayFast).

### Fault 2: Debug Artifact Leakage
* **Symptom:** `generateSignature` returned diagnostic object instead of hex string.
* **Fix:** Stripped diagnostic artifacts; returns raw hex string only.

### Fault 3: Raw Values in Hash String (NOT URL-Encoded)
* **Symptom:** Hash string contained raw URLs like `https://www.billdog.co.za/...` instead of `https%3A%2F%2Fwww.billdog.co.za%2F...`. PayFast server-side encodes values before hashing, so raw values produce a guaranteed mismatch.
* **Fix:** Applied `payfastUrlEncode()` (PHP `urlencode` parity) to all parameter VALUES in the hash string. Spaces become `+`, special chars become `%XX`.
* **CRITICAL:** The passphrase is NOT URL-encoded — it is appended raw. Only parameter values are encoded.

### Fault 4: Alphabetical Sort vs PayFast's Canonical Field Order
* **Symptom:** Code used `Object.keys().sort()` (alphabetical), but PayFast's working example from Byron uses a specific non-alphabetical field order.
* **PayFast's canonical order:** `merchant_id → merchant_key → return_url → cancel_url → notify_url → name_first → email_address → m_payment_id → amount → item_name → subscription_type → passphrase`
* **Fix:** Replaced alphabetical sorting with explicit `PAYFAST_FIELD_ORDER` array matching Byron's example exactly. `generateSignature()` now accepts `[string, string][]` ordered pairs.

### Fault 5: `email_confirmation` Field Pollution
* **Symptom:** `email_confirmation: "0"` was included in the payload and hash string, but PayFast's canonical example does NOT include this field. Its presence corrupts the signature.
* **Fix:** Removed `email_confirmation` entirely.

### Fault 6: Silent `undefined` in URLs
* **Symptom:** Missing `PAYFAST_ITN_URL` env var silently became the string `"undefined"`.
* **Fix:** Explicit env var validation in API route; aborts with 503 if missing.
